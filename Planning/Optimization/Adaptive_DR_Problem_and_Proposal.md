# 게임 속 공학적 문제의 구체화와 해결 아이디어 제안

## 주제: 다수의 원격 이동 객체에 대한 네트워크 갱신 비용과 상태 정확도의 균형

작성일: 2026-09-09  
대상: Unreal Engine 5.7 기반 멀티플레이 게임  
참고 논문: S-J. Yu, Y-C. Choy, *An Adaptive Dead Reckoning Algorithm using Update Lifetime*, Virtual Reality 5, 132–148 (2000).

이 문서는 프로젝트를 제안하기 위한 문제 정의와 해결 논리를 정리한다. 논문에서 확인된 사실, Unreal의 기존 기능, 이번 프로젝트의 추가 아이디어를 구분하며, 제안 방식의 성능은 향후 실험으로 검증한다.

## 1. 게임 안에서 어떤 상황이 문제가 되는가?

### 1.1 구체적인 게임 상황

여러 플레이어가 같은 공간에서 다수의 적 NPC를 관찰하는 협동 게임을 가정한다. 서버는 NPC의 이동과 전투를 결정하고, 각 클라이언트는 전달받은 상태를 이용해 NPC를 표시한다. NPC들은 서로 다른 방식으로 움직인다.

| 객체 | 게임 속 움직임 | 동기화에서 고려할 점 |
|---|---|---|
| NPC A | 일정 속력으로 길을 따라 직선 이동 | 마지막 위치·속도로 이후 위치를 비교적 잘 예측할 수 있음 |
| NPC B | 장애물을 피해 반복적으로 방향 전환 | 이전 이동 기준이 자주 부정확해짐 |
| NPC C | 플레이어를 향해 돌진하거나 공격 준비 | 작은 위치·방향 오차도 플레이어의 회피 판단에 영향을 줄 수 있음 |
| NPC D | 정지해 대기 | 이동 변화가 없으므로 기존 변경 감지·휴면 기능이 효과적일 수 있음 |

이 중 핵심 연구 대상은 **클라이언트에 보여야 하며, 계속 움직이고 있는 NPC A·B·C**다. 관련성이 없는 객체를 제외하거나 정지 객체의 갱신을 줄이는 것만으로는 이들의 이동 정보 비용이 모두 해결되지 않는다.

### 1.2 비용과 품질이 충돌하는 이유

이동 상태를 자주 전달하면 방향 전환이나 급정지를 클라이언트에 더 빨리 반영할 기회가 생긴다. 그러나 다수의 객체와 관찰자가 동시에 존재하면 상태 수집·복제 처리와 전송에 비용이 든다. 연결의 대역폭이 부족해지면 일부 갱신이 뒤로 밀릴 수 있다.

반대로 갱신을 일괄적으로 줄이면, 예측 가능한 직선 이동에서는 문제가 작을 수 있지만 급정지·회전·돌진 구간에서는 클라이언트가 오래된 상태로 이동을 재구성할 수 있다. 사용자는 NPC가 미끄러지거나 갑자기 보정되는 모습, 화면상 위치와 서버 판정 사이의 차이를 경험할 수 있다.

여기서 중요한 구분은 **“위치 값이 변했다”와 “새 위치를 전달해야 정확하게 표시할 수 있다”가 같지 않다**는 점이다.

예를 들어 NPC가 초당 200cm로 등속 직선 이동하면 0.1초 동안 실제 위치는 20cm 변한다. 하지만 이전 위치와 속도를 정확히 알고 같은 시각을 기준으로 계산한다면 그 20cm 이동을 새 메시지 없이도 예측할 수 있다. 따라서 20cm의 상태 변화가 곧 20cm의 예측 오차를 의미하지는 않는다. 실제 환경에는 지연·양자화·충돌 등이 있으므로 이 예측이 얼마나 맞는지는 측정해야 한다.

### 1.3 공학적 문제 정의

> **다수의 관련 있는 원격 이동 객체가 존재할 때, 객체별 이동 예측 가능성과 게임상 중요도의 차이를 고려하여, 클라이언트 상태 오차를 허용 수준으로 유지하면서 이동 갱신에 필요한 통신 및 처리 비용을 줄이는 문제다.**

이 문제의 목표는 전송량 최소화 하나가 아니다. 제한된 자원 안에서 정확도를 유지하는 최적화 문제로 본다.

```text
줄이려는 비용: 실제 통신량 + 이동 동기화를 위한 처리 비용
지켜야 할 조건: 허용 위치·방향 오차, 중요 행동의 반영 지연, 게임 상태의 정확성
조절할 대상: 이동 기준 상태의 갱신 시점과 전송 필요도
```

통신 비용과 CPU 비용은 따로 측정한다. 통신을 줄이기 위해 예측 계산을 추가하면 CPU가 늘 수도 있다. 현재 게임에서 이 문제가 어느 정도로 발생하는지는 먼저 프로파일링하여 확인한다.

## 2. 기본 Unreal Engine은 이 문제를 어떻게 해결하는가?

### 2.1 기본 복제도 이미 선택적으로 동작한다

Unreal의 기본 네트워크 시스템은 모든 Actor의 전체 상태를 같은 주기로 무조건 전송하지 않는다. 복제 여부, 휴면, 갱신 시점, 연결별 관련성, 우선순위 등을 검사하고 변경된 속성을 전달한다. `NetUpdateFrequency`는 갱신 기회를 조절하는 값이지, 모든 클라이언트에 그 횟수만큼 실제 패킷 도착을 보장하는 값이 아니다. [Epic: Actor Replication Flow][U1]

| 기본 기능 | 해결하는 문제 | 이번 연구에서 남는 질문 |
|---|---|---|
| 변경 기반 Property Replication | 동일한 속성 값을 불필요하게 반복 전달하는 비용을 줄임 | 위치가 바뀌었어도 이전 정보로 재구성할 수 있는가? |
| Relevancy | 특정 클라이언트에 필요 없는 Actor를 복제 대상에서 제외 | 이미 관련성이 있는 이동 Actor 사이에서도 갱신 필요성이 다른가? |
| Dormancy | 자주 변하지 않는 Actor의 복제 검토 비용을 줄임 | 계속 움직이는 객체의 비용은 어떻게 줄일 것인가? |
| NetUpdateFrequency | Actor별 갱신 기회를 조정 | 같은 빈도가 직선 이동과 급회전 모두에 적절한가? |
| Adaptive Net Update Frequency | 의미 있는 복제가 적은 Actor의 불필요한 복제 시도를 줄임 | 의미 있는 속성 변화가 계속 있어도 예측 오차는 작을 수 있지 않은가? |
| Priority | 대역폭이 부족할 때 중요도에 따라 복제 자원을 배분 | 이동 재구성 오차의 위험을 추가로 고려할 가치가 있는가? |

근거: [복제 흐름][U1], [Property Replication과 Adaptive Update][U2], [Dormancy][U3], [Actor Priority][U4]. Adaptive Update의 개념 설명은 공식 5.2 문서를 참고하고, 5.7.4의 일반 복제 구현은 기존 상세 계획서에서 로컬 엔진 소스로 교차 확인했다.

Adaptive Net Update Frequency가 보는 “의미 있는 갱신”에는 복제 속성의 변경이 포함된다. 등속 이동도 위치 속성을 계속 바꾸므로, 이 기능이 자동으로 “수신자가 정확히 예측할 수 있으니 위치 갱신을 생략하자”는 판단까지 하는 것은 아니다.

### 2.2 캐릭터 이동에는 이미 예측과 보정이 있다

Character Movement Component(CMC)는 소유 플레이어의 로컬 이동 예측, 서버의 이동 검증, 필요 시 보정과 저장된 이동의 재실행을 제공한다. 서버 AI나 다른 플레이어를 보는 클라이언트의 Simulated Proxy도 이동 상태를 받아 시뮬레이션하고 시각적으로 부드럽게 보정한다. [Epic: Networked Movement in CMC][U5]

따라서 이번 프로젝트는 엔진에 예측 기능을 처음 추가하는 작업으로 설명하면 안 된다. 구분해야 할 질문은 다음 두 가지다.

- **기존 이동 재구성:** 업데이트 사이에서 캐릭터를 어떻게 움직이고, 받은 상태와의 차이를 어떻게 보정할 것인가?
- **이번 연구의 갱신 정책:** 수신자가 현재 이동을 충분히 재구성할 수 있을 때, 새 이동 기준을 얼마나 더 늦게 제공해도 되는가?

CMC의 소유자 이동 검증·보정도 오차를 사용한다. 다만 소유 플레이어의 입력을 검증하는 경로와, 여러 관찰자에게 NPC 이동 상태를 제공하는 경로는 다르다. 이 연구는 우선 **서버가 제어하는 NPC를 관찰 클라이언트에 동기화하는 비용**을 대상으로 한다.

### 2.3 Iris의 역할

Iris는 객체 상태를 수집·양자화하고, 연결별 필터와 우선순위 등을 사용해 복제를 처리하는 엔진 시스템이다. 본 프로젝트의 게임별 이동 오차 정책을 구현할 기반으로 사용할 수 있다. [Epic: Introduction to Iris][U6]

Iris의 우선순위는 누적되고, 우선순위가 높아도 대역폭 조건에 따라 그 프레임에 전송되지 않을 수 있다. 따라서 “Priority를 낮추면 원하는 주기만큼 정확히 덜 보내고, 높이면 즉시 보낸다”는 제어기로 해석하지 않는다. [Epic: Iris Prioritization][U7]

## 3. 기존 기능을 적용한 뒤에도 어떤 개선 가능성이 남는가?

기본 기능을 제대로 설정한 뒤, 다음 조건이 함께 나타나는지를 확인한다.

1. 여러 NPC가 관찰 클라이언트의 관련성 범위 안에 있다.
2. NPC가 계속 움직여 위치 상태가 지속적으로 바뀐다.
3. 그중 일부 구간은 적은 이동 기준 정보로도 충분히 재구성할 수 있다.
4. 모든 객체의 갱신 주기를 낮추면 급변하거나 중요한 객체의 품질이 나빠진다.

이 경우 추가 정책의 판단 기준으로 **변경 여부와 함께 재구성 오차를 활용할 수 있다.** 즉 “변화가 있는 객체를 보낸다”는 판단을 보완하여, “현재 이동 모델과 마지막 기준 상태만으로 표현했을 때 허용 오차를 넘는가”를 평가한다.

이것은 엔진 기능 전체의 결함을 주장하는 것이 아니라, **특정 게임의 움직임 특성을 이용해 기본 복제 위에 추가 최적화 여지가 있는지 검증하는 제안**이다. CMC와 적절한 주기 설정만으로 이미 품질·비용 목표를 충족한다면 추가 정책의 가치는 작을 수 있다.

## 4. 논문은 어떤 아이디어를 제공하는가?

### 4.1 기본 Dead Reckoning: 이전 이동 정보가 유효한 동안 사용한다

Dead Reckoning(DR)은 마지막으로 공유한 위치·속도·시각으로 현재 위치를 외삽하는 방법이다. 송신 측도 같은 기준으로 예측하고 실제 위치와 비교하여, 오차가 허용 임계값을 넘으면 새 기준 상태를 제공한다. [논문: PDF 6쪽 / p.137, 식 (1), Fig.7]

```text
예측 위치 = 마지막 기준 위치 + 마지막 기준 속도 × 경과 시간
위치 오차 = 실제 위치와 예측 위치 사이의 거리

오차가 허용값 이내이면: 기존 기준으로 계속 재구성
오차가 허용값을 넘으면: 새 이동 기준 상태 갱신
```

여기서 비교 기준은 바로 이전 프레임이 아니라 **수신자가 사용하는 마지막 공유 상태**다. 실제 구현에서는 게시·전송·수신이 다르므로 수신 상태를 어떻게 추정하고 확인할지도 필요하다.

### 4.2 논문의 추가 아이디어: 허용 오차 자체를 적응적으로 바꾼다

고정 임계값 DR은 임계값이 작으면 정확하지만 갱신이 많아지고, 크면 갱신은 줄지만 오차가 커진다. 논문은 아바타의 회전 빈도가 달라지는 환경에서 이 절충을 동적으로 조정하는 **Dynamic Dead Reckoning(DDR)**을 제안한다.

논문의 State Update Lifetime(SUL)은 연속한 두 상태 업데이트 사이의 시간이다. 논문은 짧은 SUL을 가진 구간에서 각 업데이트의 기여도가 작아진다고 해석하고, 회전 간격의 최근 이력으로 이동 활동의 변화를 평가한다. [논문: PDF 7–9쪽 / pp.138–140]

```text
회전 이벤트 간격과 그 이력 분석
              ↓
최근 회전이 상대적으로 잦은지 평가
              ↓
회전이 잦은 구간에서는 허용 위치 오차 임계값을 확대
              ↓
일부 정확도를 교환하여 업데이트 증가를 억제
```

**“회전이 잦으니 무조건 더 자주 보낸다”가 논문 원형의 핵심은 아니다.** 회전이 잦아질수록 허용 오차를 키우는 것이 핵심이다. 다만 회전 때문에 오차도 빨리 커지므로 절대적인 메시지 수가 반드시 감소하는 것은 아니며, 논문은 고정 임계값 방식 대비 메시지 증가를 완화하는 방향을 연구한다.

논문의 REM은 속력 변화를 직접 고려하지 않고, 실험의 DDR 위치 임계값은 2–10m다. 따라서 이를 현대 전투 게임에 그대로 적용하지 않고 게임에 맞는 제한과 추가 조건을 설계해야 한다. [논문: PDF 9·13쪽 / pp.140·144]

### 4.3 논문이 보여 준 가능성과 한계

논문은 여러 고정 임계값 실험의 평균인 MTDR 대비 평균 메시지를 약 7.6% 줄였고, 평균 외삽 오차는 약 12.8% 증가했다고 보고한다. 이는 Unreal 대비 성능 결과가 아니며, 정확도를 유지한 채 일방적으로 비용만 줄였다는 결과도 아니다. [논문: PDF 16쪽 / p.147, Table 9]

이 연구에서 가져올 아이디어는 **객체 움직임의 이력에 따라 허용 오차를 조절하면서 통신 비용과 정확도의 균형을 바꿀 수 있다는 것**이다. 그 절충이 현재 게임에서 유용한지는 새롭게 검증해야 한다.

## 5. 게임에 적용할 해결 아이디어 제안

### 5.1 제안: 게임 중요도로 제한한 적응형 이동 갱신

> **기본 Unreal 복제와 이동 재구성을 바탕으로, 마지막 이동 기준의 재구성 오차와 회전 이력을 평가하고, 게임상 허용 품질 안에서 새 이동 상태의 갱신 필요성을 조절하는 정책을 제안한다.**

논문 DDR의 임계값 조정에 게임 품질 제한을 추가한다. 이 품질 제한은 논문 원형에 없는 프로젝트의 확장 아이디어다.

```text
실제 적용할 허용 오차
    = min(논문 방식으로 계산한 가변 임계값,
          해당 게임 상황에서 허용하는 최대 오차)
```

| 상황 | 제안 정책 | 기대하는 변화 |
|---|---|---|
| 일정 속력의 비전투 NPC | 재구성 오차가 작으면 이동 기준 갱신을 유예 | 예측 가능한 구간의 이동 전송 감소 |
| 회전이 잦은 비전투 군중 | 회전 이력으로 임계값을 조정하되 품질 상한 적용 | 작은 경로 차이를 허용하여 갱신 증가 억제 |
| 공격·돌진·상호작용 대상 | 오차 허용 범위를 엄격하게 유지하거나 기존 고품질 정책 사용 | 중요한 행동의 표현 품질 유지 |
| 급정지·순간이동·이동 모드 변경 | 기존 예측 기준을 갱신하고 긴급 복제 검토 요청 | 잘못된 외삽이 오래 이어지는 상황 완화 |
| 정지 상태 | 기존 변경 감지와 적절한 휴면 활용 | 불필요한 새 정책 비용을 추가하지 않음 |

높은 게임 중요도는 회전 빈도와 독립적으로 결정한다. 회전이 많은 공격 중 NPC와 회전이 많은 배경 군중에 같은 허용 오차를 적용하지 않는다. 거리만으로 중요도를 결정하지 않고 전투·표적·상호작용 관계를 함께 사용한다.

### 5.2 실제 처리 흐름

1. 서버가 현재 위치·속도·방향과 회전 이벤트 이력을 수집한다.
2. 마지막 기준 상태를 이용해 수신 측의 이동 재구성 오차를 계산하거나 추정한다.
3. 회전 이력으로 논문 방식의 가변 임계값을 계산한다.
4. 게임 중요도에 따른 허용 오차 제한과 급변 이벤트 조건을 적용한다.
5. 갱신이 필요하면 새 이동 스냅샷을 복제 대상으로 게시한다.
6. Unreal이 실제 복제를 수행하고, 클라이언트는 받은 기준으로 이동을 재구성·보정한다.

비물리 실험 Actor에서는 위치·속도·기준 시각을 묶은 이동 스냅샷으로 이를 검증한다. 현재 게임의 CMC 적 캐릭터에는 기존 이동 경로를 유지한 관측 실험부터 적용한다. 단순 선형 예측이 실제 CMC 오차를 잘 설명하지 못하면 동일 알고리즘을 그대로 이식하지 않는다.

### 5.3 Iris를 사용한다면 무엇을 추가할 수 있는가?

Iris는 위 정책이 만든 갱신을 처리하는 기반으로 사용한다. 대역폭이 부족한 조건에서는 공간적 중요도에 재구성 오차 위험과 게임 중요도를 더해, 먼저 처리할 가치가 큰 객체의 우선순위를 높이는 방식을 추가로 검증한다.

여기서는 두 기능을 구분한다.

- **갱신 정책:** 새로운 이동 기준을 제공할 필요가 있는지 판단한다. 불필요한 이동 상태 게시를 줄이는 역할이다.
- **전송 우선순위:** 갱신이 필요한 객체들이 자원을 경쟁할 때 처리 순서를 조정한다. 중요한 객체의 지연을 완화하려는 역할이다.

우선순위 조절만으로 정확한 갱신 주기나 오차 상한을 보장하지 않는다. 따라서 Iris 사용 자체보다 먼저, 오차 기반 갱신 정책이 기본 기능 대비 유효한지를 확인한다.

### 5.4 게임 품질을 지키기 위한 조건

허용 오차를 위치 값 하나로만 평가하지 않는다. 방향 오차, 중요한 변화가 반영되기까지의 지연, 오차가 허용 범위를 넘은 시간도 함께 본다. HP·사망·스킬 상태 등은 이동 오차를 이유로 억제하지 않는다.

또한 서버가 새 상태를 게시했다고 모든 클라이언트가 즉시 수신한 것은 아니다. 패킷 손실과 연결별 지연을 고려해 마지막 적용 상태를 계측하고, 최대 갱신 간격과 오래된 상태의 복구 정책을 둔다. 이 조건들은 위험을 줄이는 장치이며 네트워크 상태와 무관한 절대적 오차 보장은 아니다.

## 6. 어떤 개선을 검증할 것인가?

비교 기준은 기본 설정 하나로 한정하지 않는다. 관련성·휴면·주기·기존 이동 재구성을 적절히 적용한 Unreal 구성을 기준으로 한다.

| 비교 | 확인할 내용 |
|---|---|
| 기본 기능을 조정한 Unreal vs 제안 시스템 | 게임 수준에서 추가 이득이 있는가? |
| 동일 수신 모델의 주기 갱신 vs 고정 임계값 DR | 예측 오차로 갱신을 생략하는 효과가 있는가? |
| 고정 임계값 DR vs 논문 DDR | 회전 이력에 따른 임계값 조정 자체가 도움이 되는가? |
| 논문 DDR vs 게임 품질 제한형 DDR | 중요한 객체의 품질 저하를 통제할 수 있는가? |
| 동일 갱신 정책의 기본 Iris priority vs 오차 위험 priority | 포화 상태에서 중요한 객체의 지연·오차가 줄어드는가? |

핵심 판단 기준은 **동일한 품질 조건을 충족하면서 실제 전체 통신량을 줄였는가**, 또는 **동일한 통신 예산에서 중요한 객체의 품질을 높였는가**다. 실제 bytes, 정책 계산을 포함한 서버 CPU, 같은 시각 기준의 위치·방향 오차, P95/P99 오차, 초과 지속 시간, 중요 행동의 반영 지연을 측정한다.

고정 DR만으로 충분한 이득을 얻고 DDR의 추가 이득이 없다면, 그것도 중요한 연구 결과다. 기본 CMC나 주기 조정만으로 더 좋은 결과가 나오면 해당 기본 구성을 선택한다. 현재 게임에서 개선된다고 사전에 단정하지 않는다.

## 7. 제출용 제안 요약

멀티플레이 게임에서 서버는 여러 클라이언트에 다수 NPC의 이동 상태를 전달해야 한다. 이때 객체마다 이동 예측 가능성과 게임상 중요도가 다르기 때문에, 갱신을 자주 하면 통신·처리 비용이 증가하고 일괄적으로 줄이면 급격한 움직임이나 중요한 행동의 표현 정확도가 저하될 수 있다. 본 프로젝트는 이러한 비용과 정확도의 균형을 공학적 문제로 정의한다.

Unreal Engine은 이미 변경 기반 복제, 관련성 판정, 휴면, 적응형 갱신 주기, 우선순위, 캐릭터 이동 예측과 보정을 제공한다. 이 기능들은 불필요한 복제를 줄이고 원격 이동을 재구성하지만, 계속 변하는 위치 정보가 마지막 이동 기준만으로도 충분히 예측 가능한지에 따라 추가로 갱신을 줄일 여지는 게임의 움직임 특성에 따라 남을 수 있다.

이를 검증하기 위해 Dynamic Dead Reckoning 논문의 회전 이력 기반 가변 임계값 아이디어를 활용한다. 마지막 기준 상태로 계산한 이동과 실제 이동의 차이를 평가하고, 회전 이력에 따라 허용 오차를 조절하여 이동 갱신의 필요성을 판단한다. 논문 원형은 회전이 잦을 때 오차 임계값을 키우므로, 게임 적용에서는 전투·상호작용 중요도에 따른 품질 상한과 급변 시 갱신 조건을 추가한다.

제안의 목표는 예측 가능한 비전투 이동의 갱신 비용을 줄이면서 중요한 객체의 표현 품질을 유지하는 것이다. 적절히 설정한 Unreal 기본 기능과 고정 임계값 DR을 비교 대상으로 두고, 실제 통신량·CPU·클라이언트 오차·반영 지연을 함께 측정하여 어떤 조건에서 개선이 가능한지 평가한다.
