# 최근 5년 Latency Compensation 논문과 Unreal 구현 후보

조사 기준일: 2026-09-09  
논문 범위: 2021-09-09 ~ 2026-09-09  
비교 대상: 현재 프로젝트와 맞춘 Unreal Engine 5.7의 공식 제공 기능

## 1. 선정 결과

기존 Adaptive Dead Reckoning 프로젝트를 발전시키려면 **2024년 Predictive Dead Reckoning의 원격 차량 궤적 예측**을 우선 추천한다. 문제를 작게 정의하고 게임에서 효과를 보여주는 것이 우선이면 **2022년 Attribute Scaling의 지연별 판정 시간 조절**이 적합하다. 최신 연구와 PvP 공정성이 중요하면 **2026년 Adaptive Time Delay**를 선택할 수 있다.

아래 네 연구는 원문을 확인한 구현 후보다. 성능 수치는 각 논문의 비교군에 대한 결과이며, **UE 5.7 기본 기능을 이겼다는 증거로 사용할 수 없다.** Unreal 적용 예제와 평가 설계는 이 문서의 제안이며 구현·검증이 아직 이루어지지 않았다.

| 후보 | 출판 | 해결 목표 | 제안 예제 | 구현 난도 판단 |
|---|---|---|---|---|
| Predictive Dead Reckoning | IEEE Transactions on Games, 2024; 온라인 선공개 2023 | 원격 차량 궤적 오차와 갱신 사이의 부자연스러운 이동 | 두 차량의 추월·급회전, 이후 원격 선박으로 확장 | 중상: 학습과 UE 이식 필요, 공개 코드 있음 |
| Adaptive Time Delay | ACM FDG, 2026-08 | 다른 지연을 가진 PvP 플레이어의 공정성과 조작 반응성 사이 균형 | 엄폐물 사이에서 교전하는 1:1 아레나 | 중상: 지연 삽입 위치와 기존 예측의 상호작용이 핵심 |
| Real-time latency prediction / CLAAP | Computer Networks, 2025 | 지연 변화에 맞춰 추가 상태 예측의 실행을 선택 | 네트워크 악화 시에만 고비용 차량 예측 실행 | 상: 지연 예측과 상태 예측을 모두 검증해야 함 |
| Attribute Scaling | IEEE QoMEX, 2022-09 | 지연에 의해 떨어지는 조준·타이밍 과제 수행 능력 | 리듬 타깃, 협동 보스 패링 판정 | 중: ML 없이 최소 예제 가능, 게임별 보정 모델 필요 |

네트워크의 실제 전송 지연, 입력 후 화면 반응까지 걸리는 시간, 원격 객체의 표시 시점 지연은 서로 다르다. 이 연구들은 주로 지연의 영향을 완화한다. 이를 모두 “핑 감소”로 표현하면 연구 목적과 결과를 잘못 설명하게 된다.

## 2. Unreal은 이미 무엇을 해결하는가?

여기서 ‘기본 기능’은 엔진이 제공하는 기능을 뜻한다. 모든 프로젝트에서 아래 기능이 자동으로 활성화되거나 완성된 게임 규칙으로 동작한다는 뜻은 아니다.

| UE 기능 | 공식 문서에서 확인되는 역할 | 프로젝트에서 추가로 검증할 문제 |
|---|---|---|
| Character Movement Component, CMC | 소유 클라이언트에서 이동을 먼저 실행하고 기록한다. 서버 확인·수정 후 미확인 이동을 재실행하며, 원격 캐릭터는 복제 상태와 스무딩을 사용한다. | 내 이동의 즉각적인 반응과 상대의 미래 행동을 정확히 예측하는 문제는 구분해야 한다. 차량 전용 학습 예측기가 자동 제공되는 것은 아니다. |
| Networked Physics의 Predictive Interpolation | 클라이언트·서버 속도, RTT와 상태 수신 간격을 고려해 물리 상태를 보정한다. 예측한 힘과 상호작용을 처리한다. | 급회전·충돌에서 어느 정도 오차와 시각적 보정이 남는지 측정한다. |
| Networked Physics의 Resimulation | 물리 상태 이력을 저장하고 같은 프레임의 서버 상태와 비교해 필요하면 되감기·재시뮬레이션한다. | 정확도 개선에 드는 CPU·메모리 비용을 포함해 학습 기반 방식과 비교한다. |
| GAS의 Local Predicted 실행 정책 | 능력의 일부를 로컬에서 예측 실행할 수 있다. | 능력을 즉시 시작하는 것과 서버가 패링 성공을 어떤 시간 기준으로 판정하는 것은 별도 설계다. |
| Iris | 복제 데이터 관리, 필터링, 우선순위 등 복제 시스템을 제공한다. | 학습 궤적 예측, 게임별 판정 관대함, 교전별 지연 평준화는 별도 정책이다. |

근거: [Epic CMC 5.7 문서](https://dev.epicgames.com/documentation/unreal-engine/understanding-networked-movement-in-the-character-movement-component-for-unreal-engine?application_version=5.7), [Networked Physics 5.7](https://dev.epicgames.com/documentation/en-us/unreal-engine/networked-physics-overview?application_version=5.7), [GAS 실행 정책 5.7](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/GameplayAbilityNetExecutionPolicy?application_version=5.7), [Iris 소개 5.7](https://dev.epicgames.com/documentation/en-us/unreal-engine/introduction-to-iris-in-unreal-engine?application_version=5.7).

CMC의 이동 재실행이나 물리 Resimulation을 켰다는 사실만으로 무기 명중 판정까지 과거 시점으로 자동 복원된다고 가정해서는 안 된다. 공격의 시간 기준, 대상 이력, 명중 검증은 해당 게임의 구현을 확인해야 한다.

## 3. 후보 A — 학습 기반 원격 차량 궤적 예측

**Predictive Dead Reckoning for Online Peer-to-Peer Games**  
Tristan Walker, Barry Gilhuly, Armin Sadeghi, Matt Delbosc, Stephen L. Smith.  
IEEE Transactions on Games, 16(1), 173–184, 2024. DOI: 10.1109/TG.2023.3237943.

### 논문에서 확인한 내용

차량의 갱신 사이 궤적을 신경망으로 예측하고, 로봇의 경로 추종 제어를 응용해 표시 궤적을 연결한다. 먼 차량에는 fully connected 모델, 가까운 차량에는 최근 움직임을 사용하는 LSTM 계열 모델을 제시하며 정적 장애물 충돌 후 궤적도 다룬다. 저자들은 비교한 기존 방식 대비 최대 45% 오차 감소를 보고한다. 그러나 주요 평가는 메시지 간격과 궤적 복원에 집중하며, 지연·패킷 손실 대응은 추가 연구 대상으로 남긴다. 이 수치를 “UE보다 45% 정확”으로 해석할 수 없다. [원문](https://ece.uwaterloo.ca/~sl2smith/papers/2023TOG-Predictive_Dead_Reckoning.pdf)

저자 소속 연구 조직의 저장소는 코드·학습 데이터·모델을 제공한다고 명시한다. UE용 완성 플러그인은 아니므로 학습·추론 절차의 재현과 엔진 이식이 필요하다. 출판연도는 PDF 파일명의 2023과 구분해 저자 출판 목록의 2024년 권호를 사용했다. [공개 저장소](https://github.com/ubisoft/ubisoft-laforge-predictive-dead-reckoning), [저자 출판 목록](https://ece.uwaterloo.ca/~sl2smith/publications.html)

### 제안 예제: 급회전하는 원격 차량이 옆 차선으로 튀는 문제

두 차량이 나란히 달리다가 한 차량이 급회전한다. 관측 클라이언트는 새 상태가 도착하기 전까지 상대의 최신 조향을 알 수 없어 위치를 잘못 추정하고, 갱신 도착 후 표시 위치가 크게 수정된다.

**연구 질문:** 같은 상태 수신 조건에서, 최근 궤적을 학습한 예측과 경로 추종이 UE 물리 복제보다 원격 차량의 표시 오차와 보정량을 줄이는가?

권장 최소 구현:

1. 차량 한 종류와 평면 트랙 하나에서 직진, S자 회전, 급정지를 기록한다. 학습·평가 주행 세션을 분리한다.
2. 오프라인 재생에서 같은 스냅샷을 선형 DR, 학습 예측, 학습 예측+경로 추종에 입력해 각 요소의 효과를 분리한다.
3. UE에서 서버 권위 물리 상태와 원격 표시용 프록시를 분리한다. 첫 실험은 표시 품질에 한정하며, 예측 메시를 권위 충돌 판정으로 사용하지 않는다.
4. UE Default 물리 복제뿐 아니라 Predictive Interpolation도 비교한다. 입력 기반 물리 Pawn 구성이 가능하다면 Resimulation을 추가하고, 필요한 입력·상태 트래픽도 비용에 포함한다.
5. 한 방식에서만 메시지를 더 받거나 더 긴 표시 지연을 허용하지 않았는지 확인한다. 이후 정적 장애물 충돌을 별도 단계로 추가한다.

핵심 측정값은 같은 서버 시간의 위치·회전 오차, P95 오차, 표시 위치 보정량, 표시 지연, 프레임당 추론 시간, 연결당 바이트다. 보간이 사용하는 과거 표시 시점에 정렬한 오차와 현재 서버 상태 대비 오차를 함께 기록한다. 오래된 위치를 부드럽게 보여주는 것만으로 정확도가 개선됐다고 판정하지 않는다.

현재 선박 프로젝트로의 확장은 가능성이 있지만 **차량 학습 모델을 배에 그대로 적용할 수 있다는 근거는 없다.** 부력·회전 관성·파도 조건을 반영한 데이터를 새로 확보해야 한다. 먼저 차량에서 논문 구조를 재현한 다음 선박으로 확장하는 편이 원인 분석에 유리하다.

## 4. 후보 B — 교전할 때만 추가 지연을 적용하는 공정성 보상

**Adaptive Time Delay for Improving Player Experience and Fairness in First-Person Shooter Games with Network Latency**  
Samin Shahriar Tokey, Ben Boudaoud, Josef Spjut, Mark Claypool.  
ACM FDG, 2026-08-10~13. DOI: 10.1145/3815598.3815633.

### 논문에서 확인한 내용

상대적으로 지연이 낮은 플레이어에게 항상 추가 지연을 부여하면 비전투 행동도 둔해진다. 논문은 시야·근접 여부로 상호작용을 판단하고 그때만 지연을 추가한다. 세 사용자 연구에서 고정 지연에 준하는 공정성과 더 나은 평균 경험을 보고하며, 급격한 전환보다 완만한 전환이 유리했다. 이점은 높은 지연 조건에서 두드러졌다. 입력을 큐에 넣어 실행을 늦추는 실험이며, 멀티플레이 평가는 2인이고 라운드별 기본 지연은 일정했다. 따라서 현대 UE 예측과의 조합, 실제 변동 지연, 다인전으로 결과를 일반화할 수 없다. [저자 페이지](https://web.cs.wpi.edu/~claypool/papers/adaptive-fdg-26/), [NVIDIA 논문·원문 다운로드](https://research.nvidia.com/publication/2026-08_adaptive-time-delay-improving-player-experience-and-fairness-first-person)

Last Stand 테스트베드 저장소에는 Unity 프로젝트와 지연 전환 속도 설정이 있다. 재현 자료로 참고할 수 있지만, 현재 저장소 상태가 2026년 논문의 모든 실험 설정과 일치하는지는 별도 확인해야 한다. [Last Stand 저장소](https://github.com/Tokey/LastStand)

### 제안 예제: 저지연·고지연 플레이어의 1:1 엄폐물 교전

두 플레이어가 엄폐물 뒤에서 이동하다 서로 보이면 사격한다. 비전투 구간의 조작감과 교전 중의 기회 차이를 모두 평가할 수 있도록 맵에 이동·타깃 사격 구간을 함께 둔다.

**연구 질문:** 비전투 구간에서는 빠른 반응을 유지하면서 교전 중 지연 차이에 따른 승패 편향을 줄일 수 있는가?

비교군은 UE CMC와 동일한 공격 검증을 사용하는 상태에서 추가 지연 없음, 고정 추가 지연, 교전 시 적응형 추가 지연이다. 먼저 원문의 입력 큐 실험을 작은 장면에서 재현하고, 이후 CMC 예측을 유지하는 실전 구성으로 옮겨 효과가 남는지 평가한다.

입력 전체를 늦추는지, 서버에서 행동 처리를 늦추는지에 따라 조작감과 공정성이 달라진다. 특히 CMC는 서버의 이동 처리만 늦춰도 로컬 이동을 먼저 보여줄 수 있다. 따라서 지연 삽입 지점과 예측 정책을 문서화해야 하며, 사격 RPC만 늦춘 변형은 원문 전체 재현과 구분한다.

교전 진입·이탈 시 정책이 반복 전환되지 않도록 유지 시간과 완만한 전환을 실험한다. 적응을 너무 느리게 하면 첫 사격 구간의 비대칭이 남을 수 있으므로 교전 시작 직후의 성적도 따로 집계한다. 입력 순서와 이동 시간 계산을 보존하는 큐가 필요하다.

측정은 양쪽 역할을 교환한 승률·명중률 차이, 입력 후 확인까지의 시간, 비전투 반응성, 추가 지연 적용 비율, 사용자 경험으로 한다. 총 점수만으로 공정성을 단정하지 않는다. 협동 PvE에서는 저지연 플레이어를 늦출 필요성이 약하므로 현재 프로젝트의 첫 선택보다는 독립 PvP 예제에 적합하다.

## 5. 후보 C — 지연 예측으로 고비용 보상 실행을 선택

**Real-time latency prediction for cloud gaming applications**  
Doriana Monaco, Alessio Sacco, Daniele Spina, Francesco Strada, Andrea Bottino, Tania Cerquitelli, Guido Marchetto.  
Computer Networks, 264, 111235, 2025. 온라인 공개 2025-04-10. DOI: 10.1016/j.comnet.2025.111235.

### 논문에서 확인한 내용

CLAAP은 최근 지연 표본을 사용하는 RBF 신경망과 데이터 분포 변화 감지를 결합한다. 변화 감지 시 재학습하며, 예측 지연을 이용해 게임 상태 예측 모듈의 실행을 선택한다. 게임 적용 실험은 Unity/Mirror 기반 레이싱 구성이다. 약 21% 개선은 온라인 적응의 **지연 예측 오차**에 관한 결과이며 RTT 감소가 아니다. 갑작스러운 첫 변화는 놓칠 수 있다. 공개 완성 코드는 이번 조사에서 확인하지 못했고 원문의 데이터 제공 정책은 요청 시 제공이다. [원문 및 의사코드](https://iris.polito.it/retrieve/0ba86fed-9bfd-4a79-b68b-e519c1846133/1-s2.0-S1389128625002038-main.pdf)

### 제안 예제: 네트워크 악화가 예상될 때만 추가 차량 예측 실행

원격 차량이 많으면 후보 A의 신경망을 모든 차량에 항상 실행하는 비용이 문제가 될 수 있다. 연결별 지연 이력을 이용해 추가 예측이 필요한 상황을 선택한다.

**연구 질문:** 항상 실행하는 추가 예측과 비슷한 원격 표시 품질을 유지하면서, 지연 예측을 이용해 전체 CPU 비용을 줄일 수 있는가?

비교군은 UE 기본 보상만 사용, 추가 예측 항상 실행, 현재 지연 임계값으로 실행, EWMA 기반 실행, CLAAP 기반 실행이다. 추가 예측기를 선택하는 실험이므로 각 선택 정책에서는 같은 상태 예측기와 같은 메시지 조건을 사용한다.

실험에서는 ‘다음 RTT 예측’과 ‘특정 객체의 다음 스냅샷 도착 간격 예측’을 동일하게 취급하지 않는다. 복제 스케줄링이나 패킷 손실 때문에 객체의 상태 공백은 RTT와 다를 수 있다. 예측 대상과 측정 표본의 의미를 먼저 고정한다.

UE의 필수 서버 검증이나 CMC 보정을 선택적으로 끄는 방식으로 구현하지 않는다. 선택 대상은 새로 추가한 고비용 보상 계층이다. 예측 실패 시에는 기본 보상을 유지하고, 학습·변화 감지 비용까지 포함한 총 CPU 시간을 평가한다.

갑작스러운 지연 증가, 지속적 혼잡, 정상 복귀를 포함한다. 예측 MAE 외에도 필요한 보상을 켜지 못한 비율, 불필요하게 켠 비율, P95 위치 오차, 총 CPU와 메모리를 기록한다. 단순 EWMA보다 최종 게임 품질·비용이 낫지 않다면 복잡한 모델을 채택할 이유가 없다.

이 주제는 후보 A의 후속 확장으로 권장한다. 첫 프로젝트로 선택하면 지연 예측과 상태 예측의 효과를 동시에 설명해야 하므로 범위가 커진다.

## 6. 후보 D — 지연에 따른 판정 범위·시간 조절

**Compensating for Latency in Cloud-based Game Streaming using Attribute Scaling**  
Xiaokun Xu 외. IEEE QoMEX, 2022-09-05~07. DOI: 10.1109/QoMEX55416.2022.9900875.

### 논문에서 확인한 내용

UE 4.25로 제작한 두 게임을 클라우드 스트리밍 환경에서 실험했다. Catalyst는 지연에 따라 히트박스 크기를, Nova는 리듬 타깃의 유효 판정 시간을 조절했다. 사용자 연구에서 수행 정확도 개선을 보였지만 경험 개선은 게임별로 달랐고 Catalyst의 QoE 차이는 통계적으로 유의하지 않았다. 당시 플랫폼은 Stadia였다. 공간·시간 판정을 관대하게 해 지연의 불이익을 완화하는 연구이며 정확한 상태 동기화나 실제 지연 감소와는 다르다. 원문의 보정 계수는 해당 게임과 과제에 맞춰진 값이다. [원문](https://web.cs.wpi.edu/~claypool/papers/game-scale-qomex-22/paper-final.pdf), [저자 페이지](https://web.cs.wpi.edu/~claypool/papers/game-scale-qomex-22/)

### 제안 예제: 협동 보스 공격의 패링 성공 시간

플레이어는 공격을 보고 제때 패링했다고 느끼지만 서버에 입력이 도착했을 때는 판정 시간이 지나 실패할 수 있다. 여기에는 공격 표시 지연, 입력 전송, 시간 정렬 오차가 함께 작용한다.

**연구 질문:** 올바른 시간 기준으로 패링을 검증한 뒤에도 남는 지연 조건별 성공률 차이를, 제한된 판정 시간 조절로 줄일 수 있는가?

최소 예제는 고정 위치 보스 하나, 예고 후 단일 공격 패턴, 패링 버튼 하나로 구성한다. 원문에 더 가까운 첫 재현은 리듬 타깃이며, 네이티브 멀티플레이 패링은 논문 아이디어의 확장이다. 스트리밍과 네이티브 클라이언트는 입력·영상 경로가 다르므로 보정량을 다시 측정한다.

권장 비교군:

| 비교군 | 목적 |
|---|---|
| 서버 도착 시각 + 고정 판정 시간 | 단순 구현의 문제를 확인하는 진단용. 이것만 이겨서는 충분하지 않음 |
| 서버 시간으로 정렬·검증한 입력 시각 + 고정 판정 시간 | 시간 정렬을 갖춘 실용 기준선. 프로젝트가 구현할 비교 기능이며 UE의 자동 패링 기능이 아님 |
| 동일한 시간 검증 + 지연별 제한된 판정 시간 | Attribute Scaling을 추가했을 때의 순효과 측정 |

GAS의 예측 실행으로 패링 애니메이션·효과를 즉시 시작할 수 있게 구성하더라도 성공 여부는 서버에서 검증한다. 서버가 검증한 시간 관계와 최근 지연을 이용해 허용 시간을 제한하며, 클라이언트가 주장한 과거 시각을 무제한 신뢰하지 않는다.

보정 함수는 예를 들어 기본 판정 시간에 지연별 보정량을 더하고 상한을 두는 형태로 시작할 수 있다. 이는 구현용 제안이며 논문의 회귀식을 재현한 것이 아니다. 계수는 해당 게임의 지연·성공률 데이터를 통해 정한다. 고지연에서 보정을 무제한 늘리거나 공유 충돌체를 플레이어마다 다른 크기로 바꾸기보다, 서버의 개별 판정 질의에 적용하는 편이 예제의 의미를 명확히 한다.

측정값은 지연 조건별 성공률, 기준 성공률과의 차이, 부당 성공·실패율, 실제로 확장된 시간, 피드백 확인 시간이다. 상한 때문에 회복되지 않는 구간도 기록한다. 목표는 성공률을 무조건 높이는 것이 아니라 설계한 난이도에 가까워지는 것이다.

## 7. 실험 설계 공통 기준

아래 값은 논문에서 공통으로 입증된 권장값이 아니라, 본 프로젝트를 위한 초기 실험안이다.

- 전용 서버 1개와 별도 클라이언트 2개에서 시작한다. 연결 RTT 30/80/150/250ms를 목표로 하되 실측 RTT를 결과에 기록한다.
- 일정한 지연에서 먼저 비교한 뒤 변동 지연과 손실 1%·3%를 추가한다. 설정의 지연이 편도인지 RTT인지 확인하고 송수신 양쪽 적용에 의한 중복을 피한다.
- 이동 예제는 10/20/30Hz 상태 갱신 조건을 비교한다. 설정 주기뿐 아니라 실제 수신 간격, 바이트, 서버 프레임 시간을 기록한다.
- 엔진의 초기 설정과 문제에 맞게 조정한 설정을 구분한다. 스무딩을 끄거나 부적절한 기본값을 써서 비교군을 인위적으로 약화하지 않는다.
- 알고리즘 비교에는 같은 기록 데이터를 재생하고, 실제 게임 실험에는 동일한 장면·주행 또는 역할 교환 조건을 사용한다.
- 학습에 쓰지 않은 세션을 평가한다. 시간적으로 인접한 프레임을 무작위로 섞어 학습·평가 누출을 만들지 않는다.
- 평균 외에 P95와 실패 사례를 보고한다. 반복 실행과 사용자 실험은 순서를 섞고 신뢰구간을 함께 제시한다.

UE는 패킷 지연과 손실을 에뮬레이션하는 기능을 제공한다. 이 기능은 실험 환경을 만드는 도구로 사용하고, 그 자체를 새 지연 보상 알고리즘으로 취급하지 않는다. [Epic Network Emulation 5.7](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-network-emulation-in-unreal-engine?application_version=5.7)

## 8. 선택할 프로젝트 제목과 완료 기준

### 기존 DR 프로젝트의 연속성을 우선할 때

**「학습 기반 궤적 예측을 이용한 Unreal 원격 차량의 위치 오차 및 시각적 보정 감소」**

논문 A를 중심으로 원격 차량 1종을 구현한다. 동일 수신 조건의 오프라인 비교와 UE Predictive Interpolation 비교를 완료하고, 정확도·표시 지연·연산 비용의 교환 관계를 제시한다. 선박 이식과 논문 C의 실행 선택은 후속 범위로 둔다.

### 수업 프로젝트의 문제 구체화와 시연을 우선할 때

**「네트워크 지연에 따른 패링 판정 시간 조절로 협동 전투의 난이도 편차 완화」**

논문 D를 중심으로 보스의 공격 패턴 하나만 구현한다. 시간 정렬을 갖춘 기준선과 비교해 부당 실패 감소 및 부당 성공 증가를 함께 보여준다. 효과가 없으면 시간 정렬만으로 충분한 조건을 밝혀낸 결과도 유효하다.

### 최신 연구와 공정성 분석을 우선할 때

**「교전 상황에 따른 적응형 지연 적용이 1:1 전투의 공정성과 조작 반응성에 미치는 영향」**

논문 B를 중심으로 입력 큐와 상호작용 감지, 고정·적응 지연을 구현한다. 원문 재현 조건과 UE 예측을 유지한 조건을 구분하고, 이식 후에도 성적 편향과 반응성의 균형이 개선되는지 평가한다.

## 9. 추가로 읽을 최근 자료

- Tokey 외, **Effects of Adaptive Time Delay on Quality of Experience in First Person Shooter Games**, ACM FDG 2024. DOI: 10.1145/3649921.3656993. 2026년 연구의 선행 논문으로 UE 기반 Zombiefield 예제를 확인할 수 있다. 독립적인 두 번째 알고리즘으로 세기보다는 연구 발전 과정을 읽는 자료다. [원문](https://web.cs.wpi.edu/~claypool/papers/adaptive-fdg-24/paper.pdf)
- Liu, Xu, Claypool, **A Survey and Taxonomy of Latency Compensation Techniques for Network Computer Games**, ACM Computing Surveys 54(11s), Article 243, 2022. DOI: 10.1145/3519023. 예측·시간 조작·게임 세계 조정 등 서로 다른 보상 목적을 구분하는 배경 자료다. 새로운 단일 알고리즘의 구현 논문으로 취급하지 않는다. [저자 페이지](https://web.cs.wpi.edu/~claypool/papers/lag-taxonomy/)

선정에서는 게임 적용 가능성, 원문 접근, 재현 자료, UE 제공 기능과의 차이를 우선했다. 최근 출판이라는 이유만으로 이미 CMC가 제공하는 클라이언트 예측을 다시 구현하는 연구를 우선 추천하지 않았다. 최초 계획의 2000년 Adaptive DR 논문은 이번 5년 범위에 포함하지 않는다.
